Cross-Site Scripting

XSS · Injection Attack

XSS happens when a website lets users post text or content, and that content gets shown to other visitors without being checked first. An attacker can write actual code disguised as a comment or message.

When other people load the page, their browser sees the code and runs it — because it trusts anything that comes from the website. The attacker's code can then steal login cookies, redirect the page, or silently record everything the victim types.

HOW IT WORKS

  1. 1Attacker types JavaScript into a comment box instead of a real message.
  2. 2Website saves it to the database without sanitising it.
  3. 3Next visitor loads the page — the browser sees and executes the script.
  4. 4Attacker's code runs with full access to the victim's session.

SQL Injection

SQLi · Database Attack

Most websites store your data in a database, and they use a language called SQL to look things up — like checking if your password is correct.

SQL Injection tricks the database by sneaking extra commands into a login form. Instead of just a username, you type something that breaks out of the expected query and rewrites its logic entirely — often making it return every user, which logs you in as the first one (usually admin).

HOW IT WORKS

  1. 1Website builds a query: WHERE user='?' AND pass='?'
  2. 2Attacker types ' OR 1=1-- as the username.
  3. 3Query becomes: WHERE user='' OR 1=1--' — always true.
  4. 4Database returns all users. You're in as admin.

Brute Force Attack

Credential Attack · Wordlist

A brute force attack is exactly what it sounds like: just trying every possible password until one works. Attackers don't guess randomly — they use giant lists of the most common passwords (often from real data breaches) and automated tools that can try thousands per second.

A weak password like password or 123456 will be cracked in milliseconds. A strong, unique password takes years or is practically impossible.

HOW IT WORKS

  1. 1Attacker gets a wordlist of millions of common passwords.
  2. 2An automated script submits each one in rapid succession.
  3. 3If no rate-limiting exists, thousands can be tried per second.
  4. 4Weak passwords are found almost instantly.

Distributed Denial of Service

DDoS · Availability Attack

A DDoS attack doesn't try to steal anything. Its only goal is to make a website or service completely unreachable — for everyone. It does this by sending so many fake requests that the server gets overwhelmed and can't respond to real users anymore.

The "Distributed" part means the traffic comes from thousands of different computers at once (often infected machines the attacker controls without their owners knowing), making it nearly impossible to block.

HOW IT WORKS

  1. 1Attacker controls a botnet — thousands of compromised devices.
  2. 2All devices are told to flood one target with requests simultaneously.
  3. 3The target's bandwidth and CPU are completely consumed.
  4. 4Legitimate users get timeouts. The service is effectively down.
